# Trace Specification: Digital Mazdoor

Reasoning traces are the primary differentiator of this system. They must be consistent, human-readable, and machine-parsable.

## 1. Trace Structure

Each agent must output a `TraceStep` object:

```typescript
interface TraceStep {
  agent_id: string;        // e.g., "ranking_agent"
  timestamp: string;       // ISO 8601
  status: "success" | "failure" | "warning";
  input_summary: string;   // Brief description of what the agent received
  reasoning_logic: string[]; // Step-by-step logic used to reach a decision
  decision: any;           // The final output of the agent
  confidence: number;      // 0.0 to 1.0
  metadata: Record<string, any>; // Additional technical data (e.g., scoring breakdown)
}
```

## 2. Agent Specific Traces

### 2.1 Intent Agent
- **Reasoning**: "Detected language: Roman Urdu. Keyphrases: 'AC', 'Gulshan', 'Kal'. Mapped 'Kal' to 2026-05-15."
- **Decision**: `{ service: "AC Repair", location: "Gulshan", time: "2026-05-15T09:00:00" }`

### 2.2 Ranking Agent
- **Reasoning**: 
    1. "Found 5 providers within 5km."
    2. "Provider A (1.2km) +30 pts for proximity."
    3. "Provider B (4.9 rating) +25 pts for quality."
    4. "Provider A reliability is 100% (+20 pts)."
- **Decision**: `Muhammad Ali (Score: 92/100)`

### 2.3 Dispute Agent
- **Reasoning**:
    1. "Provider reported 'At Location' at 10:05."
    2. "User reported 'No Show' at 10:20."
    3. "GPS trace shows Provider was actually 5km away at 10:05."
- **Decision**: `Validate User Complaint; Refund Initiated; Provider Penalized.`

## 3. UI Display Requirements

The Mobile App must render these traces in a dedicated "Agent Reasoning" drawer or card, providing:
- **Visual Iconography**: Unique icons for each agent type.
- **Collapsible Steps**: Ability to drill down into the specific logic.
- **Live Streaming**: Steps should appear as they are generated by the orchestrator.
