

# AI Service Orchestrator — Engineering Constitution

## Core Objective

Build a production-style Agentic AI Service Orchestrator for the informal economy using Google Antigravity as the primary orchestration layer.

The system must demonstrate:

* agentic reasoning
* workflow orchestration
* autonomous decisions
* provider matching
* scheduling intelligence
* booking simulation
* follow-up automation
* dispute handling
* reasoning traces

This is NOT a simple booking app.

The focus is:

* reasoning visibility
* orchestration quality
* workflow automation
* intelligent decision-making

---

# Development Philosophy

The project MUST follow:

## Spec-Driven Development (SDD)

Rules:

1. Documentation before implementation
2. Architecture before coding
3. Workflows before UI
4. Reasoning before automation
5. Modular implementation
6. Incremental development
7. Preserve architecture consistency

---

# Important Engineering Rules

DO:

* generate markdown documentation first
* explain reasoning before implementation
* maintain modular architecture
* preserve context across phases
* focus on judging criteria
* prioritize agentic workflows
* show visible reasoning traces
* keep architecture scalable

DO NOT:

* perform random vibe coding
* generate huge unstructured code dumps
* skip documentation
* overfocus on UI
* change architecture randomly
* implement features without specifications
* create unnecessary complexity

---

# Google Antigravity Rules

Google Antigravity MUST remain the main orchestration engine.

Antigravity controls:

* intent understanding
* agent coordination
* workflow execution
* provider ranking
* scheduling
* pricing
* booking simulation
* follow-up workflows
* dispute workflows
* reasoning traces

External APIs/LLMs are secondary.

* distance

* provider rating
* reliability
* cancellation rate
